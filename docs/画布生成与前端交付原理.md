# 画布生成与前端交付原理

## 一、从哪里来：数据源头

画布数据来自 `analysis_result` 表的 `result_data` 字段（JSON），是 AI 分析完成后的结构化产出：

```json
{
  "factors": [
    {"id":"f_time",  "name":"时间成本", "weight":0.30},
    {"id":"f_money", "name":"金钱投入", "weight":0.20}
  ],
  "options": [
    {"id":"opt_redis",  "name":"优先学习 Redis",  "scores":{"cost":4,"time":4,"benefit":5,"risk":3,"feasibility":4}},
    {"id":"opt_docker", "name":"优先学习 Docker", "scores":{"cost":3,"time":3,"benefit":4,"risk":2,"feasibility":3}}
  ]
}
```

---

## 二、怎么生成：把列表变成带坐标的图

**核心就是把平面列表数据（factors[]、options[]）转换成可视化数据结构（nodes[]、edges[]）。**

### 流程图

```
AnalysisResultDto
  │  .getFactors() → [Factor, Factor]
  │  .getOptions() → [Option, Option]
  │
  ▼ buildAutoCanvas(dto, title)
  │
  ├─ ① 创建 root 节点（固定位置）
  │     {id:"root", type:"decision", label:title,
  │      position:{x:360, y:40}, data:{}}
  │
  ├─ ② 遍历 factors，每个 factor 生成一个 Node + 一条 Edge
  │     for (int i = 0; i < factors.size(); i++) {
  │         x = 140 + i × 560/(n-1)     ← 算水平坐标
  │         nodes.add({id:factor.id, type:"factor", position:{x, y:180}, data:{weight}})
  │         edges.add({source:"root", target:factor.id, relation:"HAS_FACTOR"})
  │     }
  │
  ├─ ③ 遍历 options，每个 option 生成一个 Node + 一条 Edge
  │     for (int i = 0; i < options.size(); i++) {
  │         x = 140 + i × 560/(n-1)     ← 算水平坐标
  │         nodes.add({id:option.id, type:"option", position:{x, y:340}, data:{scores}})
  │         edges.add({source:"root", target:option.id, relation:"HAS_OPTION"})
  │     }
  │
  └─ ④ 返回 new Canvas(nodes, edges)
```

### 坐标算法

```
root 节点：  固定 (x=360, y=40)，顶部居中

factor 节点：水平一字排开 (y=180)
  单节点：   x=360（居中）
  多节点：   x = 140 + i × (560 / (n-1))

option 节点：水平一字排开 (y=340)
  同上
```

### 结果

```json
{
  "nodes": [
    {"id":"root",       "type":"decision", "label":"学Redis还是Docker", "position":{"x":360,"y":40},  "data":{}},
    {"id":"f_time",     "type":"factor",   "label":"时间成本",          "position":{"x":140,"y":180}, "data":{"weight":0.30}},
    {"id":"f_money",    "type":"factor",   "label":"金钱投入",          "position":{"x":700,"y":180}, "data":{"weight":0.20}},
    {"id":"opt_redis",  "type":"option",   "label":"优先学习 Redis",    "position":{"x":140,"y":340}, "data":{"cost":4,"time":4,"benefit":5,"risk":3,"feasibility":4}},
    {"id":"opt_docker", "type":"option",   "label":"优先学习 Docker",   "position":{"x":700,"y":340}, "data":{"cost":3,"time":3,"benefit":4,"risk":2,"feasibility":3}}
  ],
  "edges": [
    {"id":"e_f_0","source":"root","target":"f_time",     "relation":"HAS_FACTOR"},
    {"id":"e_f_1","source":"root","target":"f_money",    "relation":"HAS_FACTOR"},
    {"id":"e_o_0","source":"root","target":"opt_redis",  "relation":"HAS_OPTION"},
    {"id":"e_o_1","source":"root","target":"opt_docker", "relation":"HAS_OPTION"}
  ]
}
```

## 三、怎么给前端：HTTP 接口

### 接口定义

```
GET /api/v1/decisions/{decisionId}/canvas
```

### 数据获取优先级

```
1. decision_canvas 表  →  用户编辑保存过的画布（优先）
2. analysis_result 表  →  AI分析结果自动生成
3. 都没有              →  返回空画布 {nodes:[], edges:[]}
```

### 完整响应

```http
HTTP 200
Content-Type: application/json

{
  "code": 0,
  "message": "success",
  "data": {
    "nodes": [ ... ],
    "edges": [ ... ]
  }
}
```

### 关键设计原则

> **画布数据独立于前端图形库**——不要在 JSON 里放 React Flow、Cytoscape 等库的内部字段。后端只给纯数据（nodes/edges），前端自己适配渲染库。

---

## 四、前端怎么渲染

前端拿到 `{nodes, edges}` 后直接丢给图形库，不需要额外计算：

```jsx
// React Flow 示例
const response = await fetch('/api/v1/decisions/d_20001/canvas');
const { data } = await response.json();

<ReactFlow nodes={data.nodes} edges={data.edges} />
```

图形库自动做三件事：

| 数据字段 | 图形库行为 |
|---------|-----------|
| `position: {x, y}` | 把节点放在画布上指定坐标 |
| `type: "factor"/"option"/"decision"` | 用预设样式渲染（颜色、形状、图标） |
| `source → target` (edges) | 在两个节点之间画连线 |
| `data: {weight, scores}` | 在节点上显示数值（如 `${weight}`、五维雷达图） |

## 五、用户编辑后怎么回来

### 保存流程

```
前端用户拖拽节点、修改权重
  │
  ▼ PUT /api/v1/decisions/{id}/canvas
  │  {nodes: [...], edges: [...]}
  │
  ▼ saveCanvas()
  │  ① 序列化新画布 → JSON
  │  ② 读旧画布做 diff → computeChangedNodeIds()
  │  ③ 存入 decision_canvas 表（新增或覆盖版本号+1）
  │
  ▼ 返回
  │  {changedNodeIds: ["f_time"], canvas: {...}}
  │
  ▼ 前端用 changedNodeIds 发起局部重推
  POST /api/v1/decisions/{id}/partial-analysis
```

### Diff 怎么算

```
旧画布节点 → 按 id 建 Map
新画布节点 → 按 id 建 Map

逐个比较：
  - 新有旧无 → "新增" → 加入 changed
  - 旧有新无 → "删除" → 加入 changed
  - 都有但位置变了 → "修改" → 加入 changed
  - 都有但 data 变了 → "修改" → 加入 changed（JSON 序列化后字符串比较）

边变更 → 两端节点都加入 changed
```

## 六、全链路一览

```
┌─ 数据库 ──────────────────────────────────────────────────────┐
│  analysis_result.result_data  {"factors":[...], "options":[...]}
└──────────────────────────────┬────────────────────────────────┘
                               │
                               ▼  Jackson 反序列化
┌─ Service 层 ──────────────────────────────────────────────────┐
│  AnalysisResultDto dto = objectMapper.readValue(json, ...)    │
│                               │                               │
│                               ▼  buildAutoCanvas()            │
│  Canvas {                                                     │
│    nodes: [                                                   │
│      {id, type, label, position:{x,y}, data:{weight/scores}}  │
│    ]                                                          │
│    edges: [{id, source, target, relation}]                    │
│  }                                                            │
└──────────────────────────────┬────────────────────────────────┘
                               │
                               ▼  Jackson 序列化 → JSON
┌─ HTTP Response ───────────────────────────────────────────────┐
│  {"code":0, "data": {"nodes":[...], "edges":[...]}}           │
└──────────────────────────────┬────────────────────────────────┘
                               │
                               ▼  fetch
┌─ 前端 ────────────────────────────────────────────────────────┐
│  <ReactFlow nodes={...} edges={...} />                        │
│                                                               │
│  position → 渲染位置                                          │
│  type     → 颜色/形状/图标                                     │
│  edges    → 连线                                              │
│  data     → 权重/分数 显示                                     │
└───────────────────────────────────────────────────────────────┘
```
