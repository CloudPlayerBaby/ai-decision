# AI 引擎开发规则 (AI Rules)

本文档包含了团队协作中作为 AI 引擎（A）开发人员必须遵循的核心规范。

## 1. Git 操作规范铁规
1. **不要未经许可 commit 和 push，可以 add。**
2. **commit 一定要是中文注释。**
3. **push 之前一定要先 pull 一下。**
4. **如果真的产生冲突（两人修改同一地方那种），一定不能擅自解决，必须立刻跟用户说明并停止操作，交由用户亲自处理。**

## 2. 角色职责边界
我是团队中的“A”（单兵作战），专注于 AI 引擎逻辑（LangGraph4j 编排、Spring AI 提示词与工具调用）。
团队中还有 B、C、D 同学负责其他模块。

**禁止修改的区域（越权）：**
- **Web Controller 层**：尤其是 SSE (Server-Sent Events) 接口、认证授权，这些由前端对接（B同学）负责。
- **异步任务外壳**：任务队列的排队、生命周期管理、数据库 CRUD 和基础设施（Docker 等），由基础同学（C/D同学）负责。

## 3. 业务 PRD v2.0 强制契约
1. **并发控制**：禁止在 AI 引擎中使用乐观锁机制。状态冲突时，直接抛出 `40901` (Status Conflict) 错误，由外层处理。
2. **数据删除**：只使用简单的物理删除，不实现复杂的软删除机制（除非外壳模块提供）。
3. **SSE Ticket 模式**：原生 `EventSource` 需要通过 `POST /analysis-tasks/{taskId}/sse-ticket` 获取 ticket。这是 B 组控制层的约定，A 组引擎内部不要重复实现，但必须在抛出事件时遵循契约结构。
4. **AI 验证与修复**：必须实现 `RepairNode`。当 AI 返回的结构化数据（JSON）校验失败时，抛出 `42201` 错误，并触发 `RepairNode` 进行最多一次的重试修复。
