# 📖 AI 情景推演决策系统 - 数据库设计与协作说明 (V2.0)

> **版本**：对齐 API v2.0 接口手册
>
> **适用数据库**：MySQL 8.x
>
> **编码格式**：`utf8mb4` / `utf8mb4_unicode_ci`
>
> **迁移文件**：`V1__init_schema.sql` + `V2__align_api_v2.sql`

## 一、 全局表结构关系（ER 概述）

核心业务围绕 **"用户创建决策问题 (decision)"** 展开，系统包含 9 张关键数据表：

```
sys_user (用户表)
  └── decision (决策问题主表)
        ├── agent_run (推演任务表)
        │     ├── agent_step (步骤及工具调用记录表)
        │     └── analysis_result (AI分析结果草案表) ← V2 新增
        ├── decision_factor (关键影响因素表)
        ├── decision_solution (候选方案及评分表)
        ├── decision_canvas (决策画布节点及连线布局表)
        └── decision_report (最终结构化决策报告表)
```

## 二、 详细数据表说明文档

### 1. `sys_user` 用户表

- **业务功能**：支持用户注册、登录、JWT 鉴权。
- **核心字段说明**：
  - `username`：登录账号，唯一索引（`uk_user_username`）。
  - `email`：邮箱，唯一索引（`uk_user_email`），支持邮箱注册和邮箱登录。
  - `password_hash`：加密存储的密码哈希值（禁止明文存储）。

### 2. `decision` 决策问题表（核心主表）

- **业务功能**：存储用户创建的决策问题背景、目标、约束及整个决策生命周期的状态机。
- **核心字段说明**：
  - `status`：决策状态流转字段（对齐 API v2.0 3.1 节）。状态包含：
    - `PENDING`（已创建，尚未推演）
    - `ANALYZING`（整轮推演进行中）
    - `PARTIAL_ANALYZING`（局部重推进行中）
    - `WAITING_CONFIRM`（结构化结果已通过校验，等待用户确认）
    - `COMPLETED`（报告已正式生成）
    - `FAILED`（推演或报告生成失败）
  - `preferred_option_id`：用户当前倾向选择的方案 ID。
  - `latest_task_id`：最近一次推演任务 ID（关联 `agent_run.id`）。
  - `has_pending_result`：是否存在待用户确认的新分析草案（0/1）。
  - `pending_result_id`：待确认草案的 ID（关联 `analysis_result.id`）。
  - `report_id`：当前最新正式报告 ID（关联 `decision_report.id`）。
  - `constraints`：约束条件，自由文本（API v2.0 要求为 string）。

### 3. `agent_run` 推演任务表

- **业务功能**：支持异步推演任务管理、刷新恢复进度、区分全量推演与局部重推。
- **核心字段说明**：
  - `run_type`：`FULL`（全量推演）/ `PARTIAL`（局部重推）。
  - `status`：`PENDING` / `RUNNING` / `SUCCEEDED` / `FAILED`。
  - `current_step` / `total_steps`：进度步骤数。

### 4. `agent_step` 推演步骤及工具调用表

- **业务功能**：持久化 Agent 分步思考过程，支持单步重试和工具调用展示。
- **核心字段说明**：
  - `step_type`：`THINKING`（思考）/ `TOOL_CALL`（工具调用）。
  - `tool_name`：工具名称（如 `web_search`）。
  - `status`：`WAITING` / `RUNNING` / `SUCCEEDED` / `FAILED`。
  - `input_data` / `output_data`：JSON 格式，入参和结构化输出。

### 5. `analysis_result` 分析结果草案表（V2 新增，API v2.0 4.2 节核心概念）

- **业务功能**：每次 AI 推演通过结构校验后生成一条草案。`analysisResultId` 贯穿选择方案、确认结果、局部重推等关键流程。每次局部重推产生新草案，旧草案保留不丢失。
- **核心字段说明**：
  - `status`：
    - `PENDING_CONFIRM` — 待用户确认。
    - `CONFIRMED` — 用户已确认，已成为正式结果。
  - `result_data`：JSON 格式，完整存储：
    - `understanding` — 问题理解
    - `factors[]` — 关键因素（id, name, weight, description）
    - `options[]` — 候选方案（id, name, pros[], cons[], risks[], scores: {cost, time, benefit, risk, feasibility}）
    - `recommendation` — 推荐（optionId, reason）
    - `nextActions[]` — 下一步行动
    - `canvas` — 画布快照
    - `validation` — 校验（schemaValid, repaired, warnings）
  - `task_id`：产生该结果的推演任务 ID。

### 6. `decision_factor` 决策影响因素表

- **业务功能**：决策关键影响因素，支持用户在画布上手动修改权重。
- **核心字段说明**：
  - `weight`：权重数值（如 `0.30`）。
  - `source`：`AI` / `USER`。

### 7. `decision_solution` 决策候选方案表

- **业务功能**：AI 推演生成的候选方案（2~3 个），包含优缺点、风险及五维评分。
- **五维评分字段**（`DECIMAL(3,1)`，1–5 分，5 最优；风险分 5=低风险）：
  - `cost_score` / `time_score` / `benefit_score` / `risk_score` / `feasibility_score`

### 8. `decision_canvas` 决策画布数据表

- **业务功能**：保存画布的可视化图结构（节点、连线、布局）。
- **核心字段**：`canvas_data`（JSON，完整 nodes + edges）、`version`（版本号）。

### 9. `decision_report` 决策报告表

- **业务功能**：用户确认后生成的结构化决策报告。
- **核心字段**：`content`（JSON，背景、目标、方案对比、推荐结论、下一步行动等）。

## 三、 开发配合注意事项

1. **外键约束**：插入数据严格先父后子；删除测试数据注意逆序。

2. **JSON 字段处理**：
   - `analysis_result.result_data`：Jackson 序列化/反序列化
   - `agent_step.input_data` / `output_data`：映射为 DTO 或 Map
   - `decision_solution.advantages` 等：映射为 `List<String>`

3. **状态机流转**（API v2.0）：
   ```
   PENDING → ANALYZING → WAITING_CONFIRM → COMPLETED
                   ↘ PARTIAL_ANALYZING → WAITING_CONFIRM
                   ↘ FAILED
   ```

4. **ID 对外映射**：DB 用 BIGINT 自增，API 返回带前缀字符串：
   - 决策 `"d_" + id`、分析结果 `"ar_" + id`、任务 `"t_" + id`、报告 `"r_" + id`

5. **V2 迁移变更清单**（`V2__align_api_v2.sql`）：
   - `sys_user` 加 `email` + 唯一索引
   - `decision` 列重命名：`constraints_text`→`constraints`、`selected_solution_id`→`preferred_option_id`
   - `decision` 加列：`latest_task_id`、`has_pending_result`、`pending_result_id`、`report_id`
   - 全局状态注释统一为 API v2.0 枚举值
   - 新增 `analysis_result` 表
